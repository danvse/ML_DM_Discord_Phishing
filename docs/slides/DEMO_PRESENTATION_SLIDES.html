  • Industry Standard: Discord AutoMod and bot filters (MEE6, Dyno) rely almost entirely on static regexes and keyword blocklists.
  • Evasion Trick 1 • Cyrillic Homoglyphs: Swapping Latin 'o' (U+006F) with Cyrillic 'о' (U+043E) looks identical to humans but breaks ASCII regex.
  • Evasion Trick 2 • Markdown Link Masking: '[discord.com/nitro](evil.xyz)' renders a blue trusted URL while routing clicks to credential harvesters.
  • Evasion Trick 3 • Casual Pretexts: Multi-turn openers ('Hey are you free right now?') contain no URLs to slip past entry filters.

To stop these scams, Discord servers usually rely on Discord AutoMod or community bots like MEE6. But almost all of them rely on basic keyword blocklists and regular expressions.



Scammers easily bypass them using three clever tricks: 1. When I benchmarked AutoMod regex against these evasion tricks, its F1-score crashed by 37.2%, dropping from 0.8598 down to 0.4876. That failure motivated my machine learning approach.

System Architecture: Dual-Stream Feature Fusion

Pairing Semantic Context with Structural Domain Invariants

PRESENTER ACTION [SLIDE: Walk through the two feature streams & explain why XGBoost beats BERT]
  • Core Security Insight: Scammers alter text in seconds, but MUST direct victims to external infrastructure they control.
  • Stream A (Semantic Meaning): 3,000 TF-IDF word n-grams (unigrams & bigrams) capture high-pressure scam language ('free', 'nitro', 'claim').
  • Stream B (Structural Invariants): 17 scalar features capture link patterns (homoglyphs, cloaked Markdown, brand edit distance, entropy).
  • Fused Representation: Concatenates into a 3,017-dimensional vector evaluated by an XGBoost gradient-boosted decision tree ensemble.
  • Why XGBoost over BERT? Runs in 1.2ms vs 150-300ms on CPU (no chat lag) and avoids subword token fragmentation on Cyrillic letters.
VISUAL Code: 17 Structural Domain Invariants (feature_extractor.py)
🎙 Presenter Spoken Dialogue (2:30 - 3:30)

On Slide 4 is the solution I designed: a Dual-Stream Feature Fusion Pipeline. The core insight is: Scammers can change their words in five seconds, but to steal credentials, they MUST send you to an external website they control.



So I split feature extraction into two streams: - Stream A (Semantic Meaning): Takes the message text and extracts 3,000 TF-IDF word features—both unigrams and bigrams—to capture high-pressure scam language like 'free', 'nitro', and 'claim'. - Stream B (Structural Clues): Extracts 17 numerical features that don't depend on specific words: it counts lookalike Russian characters, detects cloaked Markdown links, checks similarity to real brand names, and measures how random the link is.



I concatenate these into a single 3,017-dimensional vector and pass it to an XGBoost gradient-boosted decision tree ensemble.



I chose XGBoost over a heavy transformer like BERT for two practical reasons: First, speed: BERT takes 150 to 300 ms on a CPU, which causes chat backlogs on busy servers. XGBoost runs in just 1.2 milliseconds. Second, BERT's subword tokenizer fragments lookalike characters into weird pieces that degrade embeddings, whereas decision trees handle tabular structural rules naturally.

Mathematical Formulations Demystified

Levenshtein Early Exit, Shannon Entropy, and Minimax Risk

PRESENTER ACTION [SLIDE / FORMULAS: Plain-English explanation of mathematical models]
  • 1. Minimum Levenshtein Distance (d_min): Dynamic programming edit distance to canonical platforms (discord.com, steamcommunity.com).
  • • Optimization: Early-exit check skips O(NM) matrix calculation if absolute string length difference > 4.
  • 2. Shannon Domain Entropy (H(d)): Quantifies character randomness from information theory: H(d) = -Σ p(c) log2(p(c)).
  • • Natural language domains score 2.0–2.8; automated bot-generated scam strings score > 3.5 (red flag).
  • 3. Minimax Adversarial Formulation: Actively attacks training data with synthetic homoglyphs and disguised links:
  • • min_θ E [ max_{δ ∈ Δ} L(f_θ(x + δ), y) ] — forces decision trees to learn robust, evasive split boundaries.
VISUAL Formulations: Levenshtein, Shannon Entropy & Minimax Risk
🎙 Presenter Spoken Dialogue (3:30 - 4:30)

On Slide 5, let me explain the three main mathematical formulas powering Stream B in plain terms:



1. Minimum Levenshtein Distance (d_min): This measures the edit distance—insertions, deletions, or substitutions—between extracted links and real brands like discord.com and steamcommunity.com. If a scammer sends discoord.com, the distance is only 1. To make this fast, I added an early-exit check: if the length difference between the two words is already greater than 4 characters, I skip the expensive nested loops entirely because it's impossible for the edit distance to be small.



2. Shannon Domain Entropy (H(d)): This comes from information theory and measures randomness. Real company names like discord or steam use normal, pronounceable letter combinations, so they have low entropy (between 2.0 and 2.8). But automated scam bots spit out random, gibberish domains like x7k9-free-nitro.ru. Shannon entropy gives me a single number measuring how scrambled the letters are. Anything above 3.5 is an immediate red flag.



3. Minimax Adversarial Hardening: Instead of just training on normal scams, I formulated training as a minimax problem: my code actively attacks its own dataset during training with synthetic homoglyphs and disguised links, forcing the decision trees to learn split rules that survive sneaky tricks.

  • The 100% Recall Artifact: The model caught 178 of 178 test scams (1.0000 recall).

Now in Step 5 of the pipeline and on Slide 8, let's look at Minimax Adversarial Hardening:



Why did I add adversarial hardening? Because a standard model only learns from clean historical data. Now, Professor, I want to address this 100% recall with complete scientific honesty: Whenever you see 100% in machine learning, that is usually a red flag. In my case, there is a clear reason why it happened: Because I used the same mutation script (build_adversarial_variant) to create the training mutations as I did to evaluate the test set, the decision trees learned that homoglyph_count >= 1 was an easy shortcut! That feature jumped from the #14 feature all the way up to the #5 most important feature in tree gain.



In the open real world against brand-new zero-day attacks, recall will naturally be lower. That confirms my structural features are genuinely robust within a tight 1% variance.
